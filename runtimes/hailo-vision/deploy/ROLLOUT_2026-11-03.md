## Known SDK discovery gap

The trunk capability union advertises profile IDs `[2,1,3,5,4]`. Python main's
decoder does not yet know DECISION=5 and rejects the full capabilities frame;
this was reproduced against staging. It is **not** a failed Vision inference:
explicit known-model and task VISION requests work with the same SDK. Worker
capabilities were validated directly; signed trunk request checks explicitly
used `--skip-trunk-capabilities`, recorded in their JSON. The SDK's fail-closed
unknown-ID behavior was not changed. Resolve discovery compatibility during
point 6/cross-language conformance; full SDK discovery is not claimed here.
